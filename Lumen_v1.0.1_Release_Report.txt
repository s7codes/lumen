v1.0.1 SUMMARY
------------------------------------------------------------------------

One spec failed on GitHub Actions (ubuntu-latest) and passed locally:
tests/room-planner-3d.spec.js, "camera settings popover hides yaw, pitch,
zoom and the wireframe view until opened", at the click on
getByTestId('camera-wireframe'). Playwright reported the click target
intercepted by the bed-160 radio and a palette item inside
.room3d-layout__controls, and by a navbar link after scrolling.

Result: 105 of 105 Playwright E2E specs pass against the production build.
The fix is CSS only; no component markup changed.

------------------------------------------------------------------------
v1.0.1 ROOT CAUSE
------------------------------------------------------------------------

Measured at 1280 x 720 before the fix:
- .workspace-frame and .workspace-frame__viewport clip with
  overflow: hidden. The camera HUD and its popover live inside them.
- The HUD is a wrapping flex row: presets pill, zoom pill, fader button.
  When the row is too narrow the fader button wraps to a second row at
  the stage's left edge (x 329; stage starts at x 305).
- .camera-settings__panel is anchored right: 0 to that button and is
  256 px wide, so it opened at x 114, about 190 px past the stage's left
  edge, into the controls column (x 48 to 288).
- The overflowing part of the panel is clipped, so it is neither painted
  nor hit-testable. The centre of the Wireframe switch (x 240) landed on
  the glass controls panel. Those panels open their own stacking contexts
  through backdrop-filter and come later in the DOM, so nothing in the
  room column could outrank them.

Why only on CI: Linux fallback fonts are wider than Windows fonts, so the
HUD wraps at 1280 px on ubuntu-latest and not in local headless runs.

v1.0.1 FIX
------------------------------------------------------------------------

Files: src/styles/room3d.css, src/styles/tokens.css

Popover geometry
- .camera-settings takes margin-left: auto, so the fader button pins to
  the right edge of the HUD on whichever row it wraps to. The
  right-anchored panel now always opens inward, over the stage.
- The panel is capped at max-width calc(100vw - 48px) and max-height
  calc(100vh - nav height - 48px), scrolls internally past that, and
  contains overscroll.
- Buttons and faders in the popover carry scroll-margin-top of nav height
  + 16 px, so scrolling one into view never parks it under the sticky
  navbar.

Explicit layer order
- New tokens --z-room-stage: 2 and --z-room-panels: 1.
- .room3d-layout__main is position: relative at --z-room-stage;
  .room3d-layout__controls and .room3d-layout__inspector are relative at
  --z-room-panels. The room column outranks the glass side panels at
  every breakpoint, and all three stay inside the shell's layer (z 1),
  below the navbar (--z-nav: 20).
- .camera-settings sits at z 1 inside the HUD, above the other pills, so
  the open panel is never under the zoom pill or the notice.

Inspected, unchanged: CameraSettings.jsx, RoomToolbar.jsx, RoomViewport.jsx
and RoomPlannerPage.jsx. The markup was sound; the geometry was not.

------------------------------------------------------------------------
SUMMARY
------------------------------------------------------------------------

Lumen moves from a client-side prototype to a production application
architecture. Persistence now runs through one asynchronous client with real
network timing, the planners commit revisioned projects to Lumen Cloud,
checkout submits requisitions through the same layer, and the account reads
both back behind a loading state. Empty views carry hairline drawings and a
clear next step. The two planner workspaces ship as their own chunks behind a
centered loading frame.

Result: 105 of 105 Playwright E2E specs pass against the production build.
Zero console errors and zero CSP violations.

------------------------------------------------------------------------
1. ASYNCHRONOUS API LAYER
------------------------------------------------------------------------

Files: src/api/client.js (new)

Exports
- saveProject(kind, data)        -> { id, kind, name, revision, savedAt, data }
- loadProjects()                 -> saved projects, newest first
- submitQuote({ quote, project }) -> requisition record with its LMN-R- ref
- loadQuotes()                   -> requisitions, newest first, at most 24
- ApiError (code: 'invalid' | 'storage'), LATENCY_MS, storage keys

Transport
- Every call settles after a simulated round trip of 500 to 1200 ms,
  drawn per call. Under the hood the client writes to safeStorage:
  lumen_cloud_projects_v1 and lumen_cloud_quotes_v1.
- Payloads are serialized and sanitized when the call is made, so edits
  during the round trip never leak into the saved revision. The write
  happens only after the delay; nothing is stored on failure.
- One project slot per kind (wall, room). Each save bumps the revision.
- Empty walls and rooms are rejected with ApiError('invalid'). A refused
  storage write rejects with ApiError('storage').

Read hardening
- Every stored record is rebuilt on read. Dropped: unknown kinds (including
  "__proto__"), revisions outside 1-9999, non-ISO timestamps, wall or room
  payloads that fail sanitizeLayout or sanitizeRoomState, requisition refs
  outside LMN-R-[0-9A-F]{8}, quote ids outside LMN-Q-YYYYMMDD-XXXXXX,
  unknown currencies or statuses, and non-integer or out-of-range amounts.
- Text fields pass sanitizeText. Storage reads still go through
  safeJsonParse, which strips prototype keys at every depth.

Working drafts
- lumen_wall_studio_v1 and lumen_room_3d_v1 remain the planners' live
  drafts, so the 2D / 3D bridge, spec sheet launchers and reloads behave
  exactly as in v0.10.1. A cloud save is an explicit commit of the draft.

2. CLOUD SYNC UI
------------------------------------------------------------------------

Files: src/hooks/useCloudSave.js (new), src/components/CloudSaveButton.jsx
       (new), src/styles/cloud.css (new), src/pages/WallStudioPage.jsx,
       src/pages/RoomPlannerPage.jsx, src/components/studio/StudioSummary.jsx,
       src/components/room3d/RoomSummary.jsx, src/styles/studio.css,
       src/styles/room3d.css

Save to Cloud
- New key beside Sync Wall to Cart and Sync Room to Cart. Disabled while the
  wall or room is empty, like the sync key.
- States: idle "Save to Cloud" -> saving "Saving to Lumen Cloud..." ->
  saved "Project Saved" (held 2.4 s) -> idle. Failure reads "Retry Save"
  with a fault edge.
- Saving: the key settles flat (no lift, no plinth), dims to a neutral glass
  fill, disables itself and shows a 1px SVG arc spinning at 900 ms per turn.
  No border-radius dot, no box-shadow, no glow.
- Saved: flat inversion to solid white with a check that draws itself in.
- All labels share one grid cell, so the key never changes width between
  states. Hidden labels are aria-hidden, so the accessible name always
  matches the visible label.
- Double-commit guard: the disabled attribute plus a ref lock in
  useCloudSave. A burst of clicks during a save commits exactly one
  revision (asserted in E2E).
- Toasts: "Wall A saved to Lumen Cloud. Revision 01." / "Room saved to
  Lumen Cloud. Revision 01." Failures raise a Fault toast with the
  ApiError message. Toasts fire even if the planner unmounts mid-save.

Checkout
- Submit Project Requisition now calls submitQuote. While in flight it
  reads "Submitting to Lumen Cloud..." with the same arc and is disabled;
  the requisition confirmation appears when the call resolves.

5. CODE SPLITTING AND LAZY LOADING
------------------------------------------------------------------------

Files: src/router.jsx, src/components/RouteFallback.jsx (new),
       src/styles/shell.css

- RoomPlannerPage and WallStudioPage load through React.lazy, each inside
  its own Suspense boundary with an errorElement.
- three, @react-three/fiber and drei were already isolated in the lazy
  RoomCanvas chunk, and this release keeps them there. The overview hero is
  CSS only; there is no Hero3D component, so the home page never loads
  WebGL. An E2E spec now asserts that the overview requests no planner or
  WebGL chunk.
- Fallback: absolutely centered in the main frame (asserted within 2px).
  The Lumen mark under a sweeping mask highlight, a 160 x 1 px
  indeterminate bar, and a mono label: "Loading spatial engine" or
  "Loading wall studio". Enters with the 1.05 -> 1.0 scale, 8px blur ->
  0 focus reveal. role="status" for assistive tech.
- On client-side navigation React Router keeps the current page up until
  the chunk arrives, so the fallback appears only on a cold load.
- Chunk failure: a route error with "Workspace did not load." and a
  Reload key, instead of React Router's default error page. The navbar
  stays live.
